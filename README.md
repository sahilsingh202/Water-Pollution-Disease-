# 💧 Water Pollution & Disease Prediction

A Streamlit web app that predicts a **waterborne disease outbreak risk level**
(`High` / `Medium` / `Low`) from water quality, infrastructure, and
socioeconomic indicators, using a tuned **LinearSVC** classifier.

---

## ⚠️ Read this first — required setup step

The provided `best_water_pollution_disease_model.pkl` contains **only the
trained LinearSVC model**. It does **not** contain the `LabelEncoder`s used
on categorical columns (`Country`, `Region`, `Water Source Type`,
`Water Treatment Method`) or a feature scaler (if one was used). Without
these, the app cannot turn a user's selections into the exact numeric codes
the model was trained on.

**You must run `prepare_deployment_artifacts.py` inside your original
notebook** (the session where your fitted encoders and, if used, scaler
still exist in memory) before this app will give correct predictions.
It walks through saving:

- `feature_names.pkl` — the 23 feature names, in training order
- `label_encoders.pkl` — a dict of fitted `LabelEncoder`s for the 4 categorical columns
- `scaler.pkl` — only if you scaled your training data

The app **will run without these files** (so you can preview the UI), but
the Prediction page will show warnings and won't produce trustworthy results
until they're in place.

## 1. Save the required preprocessing files

1. Open your original ML notebook (the one where you trained the model and
   still have `X_train_clf`, your fitted encoders, and optionally your
   scaler in memory).
2. Copy the contents of `prepare_deployment_artifacts.py` into a new cell.
3. Edit the variable names in **Step 2** (categorical encoders) and **Step 3**
   (scaler) to match your actual notebook variable names.
4. Run the cell. It will produce `feature_names.pkl`, `label_encoders.pkl`,
   and (if applicable) `scaler.pkl` in your notebook's working directory.
5. Copy those files into this project folder, next to `app.py`.

If you no longer have the fitted encoder objects in memory (only the
already-encoded `X_train_clf`), see **CASE B** in the comments of
`prepare_deployment_artifacts.py` — it shows how to rebuild them from your
original (pre-encoding) dataframe, with an important caveat about matching
the original fit order exactly.

## 2. Create the Streamlit project locally

```bash
mkdir water-pollution-disease-prediction
cd water-pollution-disease-prediction
# copy in: app.py, requirements.txt, README.md, .gitignore,
# best_water_pollution_disease_model.pkl, and the .pkl files from Step 1
```

Create a virtual environment and install dependencies:

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

---

## 3. Test it locally

```bash
streamlit run app.py
```

This opens the app at `http://localhost:8501`. Check the sidebar
"System Status" panel — it should show ✅ for Model and Categorical encoders.
Go to **Prediction**, fill in the form, and click **Predict Risk Level**.
Use the "See the exact feature vector sent to the model" expander to verify
the values look correct before trusting the output.

## 5. Deploy on Streamlit Community Cloud

1. Go to [share.streamlit.io](https://share.streamlit.io) and sign in with GitHub.
2. Click **New app**.
3. Select your repository, branch (`main`), and set **Main file path** to `app.py`.
4. Click **Deploy**.
5. Wait for the build to finish — watch the logs for missing-package or
   file-not-found errors.

## 6. Troubleshooting

**"Model file not found"**
Make sure `best_water_pollution_disease_model.pkl` is committed to the repo
root, not `.gitignore`d, and not left on Git LFS without LFS being pulled by
Streamlit Cloud (Streamlit Cloud does support Git LFS, but you must enable
it — check their docs if this applies to you).

**`InconsistentVersionWarning` about scikit-learn version**
This is a warning, not necessarily a failure — but predictions can silently
differ across sklearn versions. `requirements.txt` pins
`scikit-learn==1.6.1` to match the version this model was pickled with.
If your training environment used a different version, update the pin to
match it exactly.

**Feature count / shape mismatch errors**
Almost always means the categorical encoding didn't produce a numeric value,
or a column got dropped/reordered. The app builds the row strictly in
`feature_names.pkl` order — if you added/removed a feature after saving that
file, regenerate it.

**`ValueError` — "'X' is not a category the model was trained on"**
The user selected (or a default filled in) a category value your
`LabelEncoder` never saw during training. Only values in
`label_encoders.pkl`'s `classes_` are valid; the app's dropdowns are already
populated from that list, so this should only occur if `label_encoders.pkl`
is missing or stale.

**Predictions look wrong / inconsistent with your notebook**
Most likely cause: a scaler was used during training but `scaler.pkl` wasn't
generated/uploaded, or vice versa (a scaler was uploaded but training didn't
use one). Re-check Step 3 of `prepare_deployment_artifacts.py` against your
actual notebook.
